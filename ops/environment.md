# 環境與機密管理

> 記錄「跑起來 / 建置 / 測試 / 部署」需要的環境。**領域中性**——不預設架構（web / 嵌入式 / 桌面 / 資料處理皆適用）。
> 依專案型態（§0.7），**不適用的區塊標 `不適用 (N/A)` 並一句說明**，不要留著誤導的範例。

## 1. 工具鏈就緒清單 (Toolchain Readiness) ★所有專案都要
> 由**技術棧 ADR 推導**；是 **§5 生成/建置程式碼的前置**（見 `CLAUDE.md §5` 環境就緒門檻）。
> 狀態：`未安裝` | `已安裝` | `已驗證`。**「跳過（無工具鏈）」≠「測試通過」。**

> ⚠️ 範例可刪：下方為格式示範（由 ADR 播種：SDK / 編譯器 / RTOS / runtime / DB / 框架 / 燒錄器…）。

| 工具 | 版本(定案) | 安裝方式 / 官方連結 | 安裝者 | 驗證指令 | 狀態 |
|------|-----------|---------------------|--------|----------|------|
| 例：TI SimpleLink SDK | vX | ti.com/...（需登入手動下載） | 使用者 | 檢查安裝目錄 | 未安裝 |
| 例：arm-none-eabi-gcc | vX | apt / brew / 官方 | 使用者 或 AI(經同意) | `arm-none-eabi-gcc --version` | 未安裝 |

### 安裝政策（AI 不擅自安裝軟體）
- AI 預設**只提供**：官方下載連結、安裝步驟、驗證指令，由使用者執行（大型廠商 SDK 常需登入授權，AI 無法下載）。
- 可用套件管理器（apt/brew/pip/choco…）安裝、且**使用者明確同意**時，AI 才可代跑安裝指令；仍須逐一經權限確認，**不靜默安裝**。
- AI 跑過驗證指令（version）確認後，才把狀態改 `已驗證`。
- **絕不在工具缺席時回報「已建置/測試通過」** —— 須明講「跳過：工具鏈未安裝」。

## 2. 環境變數
> 程式所需設定用環境變數管理，**不寫死在程式碼、不進版控**；實際值放各自的 `.env`（不進 Git）。
> **適用才填**（如 web／服務類）；純韌體等無環境變數的專案，整區標 `不適用 (N/A)`。

> ⚠️ 範例可刪：下方為格式示範。

| 變數名 | 用途 | 範例/預設 | 適用環境 |
|--------|------|-----------|----------|
| 例：`DATABASE_URL` | 資料庫連線字串 | `postgres://...` | 全部 |
| 例：`API_KEY` | 外部服務金鑰 | （機密） | 全部 |

> 建議額外提供 `.env.example`（只有變數名、無真實值）進版控供參照。

## 3. 機密 (Secrets) 原則
- **絕不把金鑰/密碼/憑證 commit 進 Git**（`.env`、`*.key`、`*.pem` 等已列入 `.gitignore`）。
- 若不慎提交過機密 → 視為**已外洩**，須立即輪替（rotate），不能只刪 commit。
- 正式環境機密建議用密鑰管理服務或 CI 加密變數，不落地。
- **無機密的專案**：明確寫「本專案無雲端機密」（`不適用 (N/A)`）。

## 4. 執行 / 部署目標
> 依專案型態（§0.7）填，不適用的維度標 `不適用 (N/A)`：
> - **軟體服務** → dev / staging / prod、部署平台。
> - **韌體** → 燒錄/除錯環境（燒錄器、驅動、VCP）、目標板。
> - **桌面 / CLI** → 目標 OS / runtime。

| 目標 | 說明 / 設定來源 |
|------|-----------------|
| 例：prod（軟體服務） | 密鑰管理服務 / 部署平台 |
| 例：目標板（韌體） | 燒錄器 + 驅動（如 XDS110 VCP） |
