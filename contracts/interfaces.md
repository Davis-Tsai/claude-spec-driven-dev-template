# 介面契約 (Interfaces)

> 專案的軟體「決定性錨點」。**非 web/DB 專案（嵌入式、協定、CLI…）常沒有關聯式 DB 或 REST API** ——
> 那時 `data-schema.sql`、`api.openapi.yaml` 標 `不適用 (N/A)`，**介面真相寫在這裡**（封包 / 序列 / 命令協定）。
> 反之 web 專案可用 SQL/OpenAPI，本檔標 N/A。**三者適用才用。**

> ⚠️ 範例可刪：下方為格式示範。

## 1. 封包 / 訊息格式
| 封包/訊息 | 方向 | 型別/ID | 佈局（欄位、型別、單位） | 備註 |
|-----------|------|---------|--------------------------|------|
| 例：狀態上報 | A→B | 0x01 | `[hdr][type][val_lo][val_hi]`；val=int16 ×10 | 小端 |

## 2. 序列 / 命令協定
> 例：UART/NMEA `$XXX,...*<XOR>`；列出命令集、鮑率、格式、回覆。

## 3. API 慣例（若有）
> 對外程式介面（函式簽章 / 回傳 / 錯誤碼）、上位機 API。

## 4. 單位與狀態定義
> 統一單位（如 deg/s×10）、狀態列舉（IDLE/RUN/DONE…）、位元組序（大/小端）。
