# 完成的定義 (Definition of Done)

> 「做完」不只是程式跑得動。一項需求/任務要**同時滿足**以下條件才算完成。
> AI 在回報「完成」前，應對照此清單逐項確認。可依專案調整。

## 軟體功能
- [ ] 對應 PRD 需求有唯一 ID，且 `ERD.md` 追溯表已更新
- [ ] 相關契約（schema / API / interfaces）已定案且彼此一致
- [ ] `acceptance/software/` 測試已撰寫，且全數通過（**跳過 ≠ 通過**）
- [ ] 程式碼由文件生成，未繞過文件手改（或手改已回補文件，見鐵則 6）
- [ ] 實機除錯得出的平台規則已回寫成 ADR／契約（見 `CLAUDE.md §5` 實機修正回寫）
- [ ] 已 commit，且 pre-commit 測試通過
- [ ] 若改動的是「已定案」文件，`changes/change-log.md` 已記錄一筆

## 硬體功能
- [ ] 硬體契約（腳位 / 時序 / 電氣 / BOM）已定案且一致
- [ ] 對應的人工量測程序（`acceptance/hardware/`）已定義，含參考標準與精度、設備干擾與隔離
- [ ] 實測值已記錄，且符合合格標準
- [ ] 實體設計檔（原理圖 / PCB）已存入 `hardware_build/`

## 建置與收尾
- [ ] **測試建置與正式建置都能編過**；診斷/測試掛勾在正式版預設關閉
- [ ] 下方「bring-up 暫改清單」**已全部清空**（每項已移除或轉為正式設計並記錄）

## 通用
- [ ] 用語符合 `charter/glossary.md`
- [ ] 相關風險已檢視（`charter/risk-register.md`）

## Bring-up 暫改清單
> bring-up / 除錯期間的**暫時改動**（診斷命令、故意卡死測看門狗、暫關某功能取基準…）一律登記於此，不只在程式註解寫「暫」。
> 收尾前逐項清掉，**清完才算完成**。危險的測試命令（如故意卡死）務必只存在於測試建置。

> ⚠️ 範例可刪：下方為格式示範。

| # | 位置（檔案/函式） | 暫改內容 | 原因 | 何時移除 / 處置 | 狀態 |
|---|-------------------|----------|------|-----------------|------|
| T-01 | 例：`src/firmware/cmd.c` `cmd_hang()` | 加「故意卡死」命令 | 驗證看門狗 | 限測試建置旗標；正式版不編入 | 開放 |
| T-02 | 例：`src/firmware/main.c` | 暫關自動煞車 | 取乾淨 RF 基準 | 基準量完即恢復 | 已清除 |
